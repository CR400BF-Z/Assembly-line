# 智能口算训练系统——项目开发文档

**项目名称：** 智能口算训练与自动评测系统  
**开发语言：** 纯 C 语言（不使用结构体，不滥用全局变量）  
**团队成员：** 师沐彬、耿国瑞、郭子博、马梓轩（组长）  
**完成日期：** 2026年11月17日

## 一、项目概述

本项目旨在开发一款符合三年级教学要求的“智能口算训练与自动评测系统”。系统能够随机生成符合数值范围约束的加减乘除口算题，接收学生作答，自动批改并记录错题，最终输出结构化的训练成绩报告。

**技术约束：** 使用纯 C 语言编写，不使用结构体，禁止滥用全局变量，完全通过函数封装与指针传递实现各模块解耦。

## 二、团队分工与模块设计

项目采用“模块化并行开发”策略，4名成员分别负责一个核心模块的开发与测试，所有模块统一在主控流水线中集成。

### 马梓轩（组长）：流水线主控与框架集成

负责模块：`main()` 主函数、`generate()` 流水线控制、`initSystem()` 系统初始化。

核心职责：

- 定义全组统一的接口规范（函数名、参数列表、指针与数组的传递方式）。
- 使用双层嵌套循环（外层 `for(k=0; k<4; k++)`，内层 `for(i=1; i<=10; i++)`）实现“4 种题型，每种 10 题”的流水线调度。
- 负责非法输入拦截：利用 `scanf` 的返回值判断，结合 `while(getchar() != '\n');` 清空缓冲区，彻底解决输入字母导致系统死循环的 Bug。
- 统管全局统计变量（如得分、正确数），负责将各模块封装的功能拼装成完整系统。

### 师沐彬：出题引擎内核

负责模块：`generateQuestion()`、`getOpChar()`。

核心职责：

- 严格限制数值范围：加法/减法在 10-99 之间；乘法在 1-9 之间（九九表范围）。
- 边界条件防御：减法强制保证 `num1 >= num2`（结果非负）；除法采用“倒推生成法”（先随机出除数和商，再相乘得出被除数），100% 保证整除，且完美避开除数为 0 的风险。
- 设计 `getOpChar()` 辅助函数，将数字 `0~3` 转换为可视化的运算符 `+ - * /`。

### 郭子博：自动评测模块

负责模块：`evaluateAnswer()`。

核心职责：

- 使用 `switch-case` 多分支结构分别计算加、减、乘、除的正确答案（每个分支均规范带有 `break`）。
- 接收主控传出的题目信息与学生答案，进行比对。
- 反馈判定结果：输出 `√` 正确 或 `×` 错误，正确答案是 `XX`。
- 返回 `1` 或 `0` 的整型结果给主控，为后续统计模块提供数据支撑。

### 耿国瑞：统计与报告生成模块

负责模块：`updateStats()`、`printReport()`。

核心职责：

- 成绩累加：答对一题加 `2.5` 分（满分 `100`），累加总分及正确/错误题数。
- 分题型统计：根据传入的题型参数 `k`，分别累计加法、减法、乘法、除法的正确题数。
- 错题本记录：将所有答错题目的题号、原题数字、运算符、学生答案、正确答案，分别存入平行的数组中（如 `wrongQNo[40]`、`wrongN1[40]` 等）。
- 格式化输出最终成绩单，包含总题数、正确率、题型分布以及详细的错题清单。

## 三、接口约定（无结构体方案）

由于未学习结构体，全组统一采用“多参数 + 指针传递”的方式进行数据交互。

- 对于需要修改的统计变量（如 `score`、`correctcount`），一律传入内存地址（如 `&score`）。
- 对于错题记录数组（如 `wrongQNo`），数组名本身退化为指针，直接传入。

## 四、异常处理与边界防护机制

本系统在开发中重点解决了以下教学场景中的异常问题：

1. **除零保护**：虽然出题模块已避免生成 `num2 = 0` 的题目，但在评测模块的 `case 3` 中依然加入了防除零判断。
2. **非法字符输入**：在 `generate` 主循环中，利用 `scanf` 的流机制拦截字母等非法输入，并提示重新输入。
3. **边界越界**：错题本数组长度设定为 40，无论学生全对或全错，均不会发生数组越界崩溃。
